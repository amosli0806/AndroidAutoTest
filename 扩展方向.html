2已知缺口与桩实现

🚧

⚙️
帮助中心与文档一致性 — 已大幅推进（各章节补齐、图片高清、文案精简），基本无残留空占位。
✅
接口自动化最小闭环 — 已落地；二期（前后置脚本、链路编排、数据驱动）仍未做。
📋
无变量 / 参数化 — 步骤参数写死，同一用例无法跑多组数据。
📋
无流程控制 — 没有 if/else 分支、循环、失败重试。
📋
无关键字复用 — 「登录」「搜索」等常用组合无法封装复用。
📋
无图像识别定位 — 对游戏 / 视频 / 自绘控件无能为力。
📋
套件能力不完整 — 无套件级报告、排序、链式执行。
📋

📋

📋
性能检测空白 — 缺流量曲线、自动基线回归、GPU 等维度。
📋

📋

3扩展方向（按优先级）

19 项规划按「高 / 中 / 常规 / 进阶 / 远期」五档组织，每项都配了一个生活化类比帮助理解。

◆ 高优先级 · 显著提升用户体验

1. 变量 / 参数化 📋 规划中

定义全局变量（设备序列号、测试账号、环境地址），步骤参数里用 ${变量} 引用；同一用例可循环跑多组数据（数据驱动）。

  • 全局变量表，元素库与步骤参数统一走一层变量替换
  • 从 CSV / Excel 读测试数据，同一用例循环执行多组数据
💡 打个比方：就像「填表模板」——表格里姓名、电话留成空格，谁来用就填谁的信息，不用为每个人重做一张表。同理，用例里把账号、设备号留成 ${占位符}，换账号换设备只改变量值，不必复制整份用例。

2. 日志过滤与搜索增强 ⚙️ 部分完成

  • ✅ 已按日志类型区分颜色（错误 / 成功 / 警告 / 信息）
  • ✅ 已做执行统计圆盘（通过 / 失败 / 通过率）
  • 📋 按日志类型快速筛选　📋 关键字搜索日志内容
💡 打个比方：像在微信里搜聊天记录——几千条执行日志里，一键筛出所有「失败」的几条，或搜关键词「超时」直接定位问题，不用逐行翻。

3. 批量操作增强 ⚙️ 部分完成

  • ✅ 已支持批量删除用例、批量删除元素
  • 📋 批量修改定位方式（如全部「资源ID」→「XPath」）
  • 📋 批量修改步骤参数（超时时间、等待时长、步骤间隔）
💡 打个比方：像 Excel 的「查找替换」——100 个步骤里所有「等待 3 秒」一次全改成「等待 5 秒」，不用一条条手改。

4. 补齐桩实现与文档一致性 ⚙️ 部分完成

  • ✅ 帮助中心各章节已按实际能力重写、补全、文案精简
  • ✅ 接口自动化已从占位走向可用
  • 📋 实现复杂手势序列真实执行（或下架该卡片）
  • 📋 接口模块二期：前后置脚本、链路编排、数据驱动
💡 打个比方：「复杂手势」现在就像只写了个舞蹈动作的名字、还没真正教机器人跳。补全后，你画出的一条轨迹能被原样回放出来。

5. 变量 / 参数化落地到语音播报 ⚙️ 部分完成

  • ✅ 唤醒词已经是「全局配置被步骤引用」的雏形
  • 📋 把唤醒词、语速等提升为可参数化变量，用例内可覆盖
💡 打个比方：现在只有一句「你好虫师」打天下；将来像「对不同的人用不同称呼」——测本田车就喊「你好本田」，测小鹏车就喊「你好小P」，在用例里各配各的。

◆ 中优先级 · 增强灵活性与可维护性

6. 关键字驱动 📋 规划中

把常用动作组合封装成「关键字」（如「登录」「搜索商品」），支持传参，用例里点一下就复用。

💡 打个比方：像手机「快捷指令 / 宏」——把「打开 App → 输账号 → 输密码 → 点登录」这 5 步打包成一个「登录」关键字，以后任何用例点一下就好，不用重复拖 5 个步骤。

7. 步骤模板 📋 规划中

保存常用步骤组合为模板（如「启动应用 → 等待 → 点击首页」），任意用例里插入复用。

💡 打个比方：像 Word / PPT 模板——「启动 → 等待 → 点首页」这套成熟流程存成模板，新用例直接套用，不用每次从零搭。

8. 测试套件增强 ⚙️ 部分完成

  • ✅ 套件创建、保存、加载、删除、自动匹配、失效清理
  • 📋 套件级执行报告与通过率　📋 套件内用例拖拽排序　📋 套件链式执行（A→B）
💡 打个比方：像「歌单」——用例按「冒烟测试」「回归测试」分组，跑完自动出这份歌单的「成绩单」（通过率），还能拖拽排序，A 歌单放完自动放 B。

9. 执行健壮性增强 📋 规划中

  • 步骤级失败重试（次数 + 间隔 + 触发条件可配）
  • 显式等待（等元素出现 / 消失 / 可点击，替代固定 sleep）
💡 打个比方：失败重试像「网不好就重发消息」——点一下没反应，自动再试两次；显式等待像「等人都到齐了再开饭」，而不是「干等 5 分钟」——页面一加载好就继续，又稳又省时间。

10. 图像识别定位 📋 规划中

新增「图像」定位方式（模板匹配 + 相似度阈值），元素库可上传参考图，执行时截图比对。

💡 打个比方：像「人脸识别解锁」或玩「找不同」——游戏里的按钮是「画」出来的（不是代码控件，看不到元素树），靠截图比对把它认出来，从而覆盖游戏、视频、自绘界面。

◆ 常规优先级 · 提升效率与易用性

11. 语音播报增强 ⚙️ 部分完成

  • ✅ 回执验证（自动判断「是否被识别」）+ 一键批量重算等待时间
  • 📋 唤醒词多套管理（按用例 / 车型切换、多条候选轮播）
  • 📋 车型模板（日志标签 + 关键词存成预设，换车一键套用）
  • 📋 执行结果校验（除「被识别」，再验「真执行了」，如地图是否全屏）
  • 📋 语音用例 ↔ 自动化用例互转
💡 打个比方：像「给不同车准备不同的话术模板」——每辆车的唤醒词、日志关键词都不一样，做成模板后换车一键套用，不用每次重新摸索；再进一步，还能验证「地图真的切成全屏了没有」，而不只是「车机听懂了没有」。

12. 性能检测增强 ⚙️ 部分完成

  • 📋 HTML 报告补充流量曲线
  • 📋 基线自动回归对比（跑完自动比对基线、判定劣化）
  • 📋 启动耗时历史趋势与基线对比
  • 📋 并入 mapauto-perf-test 的采集能力（GPU / 系统内存 / 整机 CPU 等，范围待定）
💡 打个比方：像「体检报告自动对比」——每次测完自动和上次体检结果比，哪项指标变差了直接标红提醒，不用自己逐项对照。

13. 版本控制集成（Git）📋 规划中

把项目数据、步骤、元素库等接入 Git，支持版本回滚、差异对比、分支管理。

💡 打个比方：像文档的「修订记录 / 历史版本」——用例改乱了，一键回到昨天的版本，还能看看到底改了哪几行。

14. 测试数据管理 📋 规划中

从 Excel / CSV 读取测试数据，参数化执行同一用例多组数据（与「变量 / 参数化」合并实现更合理）。

💡 打个比方：像「同一张答题卡批不同试卷」——用例就是那张答题卡，数据就是试卷，套上账号 A、账号 B、账号 C 各跑一遍，批量出结果。

◆ 进阶扩展 · 面向高级用户与团队协作

15. 插件机制 📋 规划中

允许编写自定义 Python 脚本作为新动作类型，支持热加载。

💡 打个比方：像浏览器插件、微信小程序——开发者自己写个小功能挂进去，不用等官方排期，个性化需求自己动手。

16. CI/CD 集成（命令行模式）📋 规划中

提供无界面运行模式，命令行执行用例 / 套件，生成 JUnit XML 报告，接入 Jenkins / GitHub Actions。

💡 打个比方：像「自动浇花装置」——代码一提交，后台自动把全部测试跑一遍并出结果，人不用盯着屏幕。

17. 多设备并行执行 📋 规划中

单机多设备同时执行不同用例（需先解决底层设备对象的线程安全问题）。

💡 打个比方：像「同时炒几锅菜」——多台车机 / 多块屏同时跑不同测试，回归时间从 1 小时缩到 10 分钟。

◆ 远期规划 · 生态建设

18. 云端存储与同步 📋 规划中

项目数据同步到云端，支持多端协同编辑与用例库共享。

💡 打个比方：像手机相册云备份——换台电脑，登录就能继续用，数据不丢、还能团队共享用例库。

19. 多语言支持 📋 规划中

界面支持中文 / 英文切换，便于国际化团队使用。

💡 打个比方：像手机系统的「语言」设置，一键切换，同一套软件服务不同语言的团队。

5下一阶段开发规划

按「依赖关系 + 价值」排序，每阶段可独立交付、独立验收，不做半成品。

阶段一 · 接口自动化最小闭环 ✅ 已完成（2026-09-28）

接口管理（增删改查 + 分组 + 导入导出）、多环境变量、断言引擎、单发 + 批量执行、HTML 报告，均已落地。

阶段一·二期 · 接口模块二期 📋 待排期

  • 前后置脚本（Python 钩子，处理签名 / 加解密 / 数据提取）
  • 链路场景编排（接口串联，上一步响应作为下一步入参）
  • 数据驱动（CSV / JSON / Excel 参数化，同一接口批量跑）
  • 与「自动化执行」用例互通（需先有变量 / 参数化打底）
💡 打个比方：前后置脚本像「做饭前的备菜 + 上桌前的摆盘」——请求前先签名、加密，响应后把数据提炼出来；链路编排像「接力赛」——上一个接口的返回，直接变成下一个接口的入参。

阶段二 · 变量 / 参数化 📋 目标 1~2 个版本周期

  • 全局变量表，步骤参数用 ${变量} 引用
  • 统一渲染层，元素库 + 步骤参数共用
  • 变量作用域三级：全局 → 用例 → 步骤
  • 数据驱动：从 CSV / Excel 读数据，循环跑多组
💡 打个比方：又是「填表模板」——这是关键字驱动、数据驱动、接口 UI 混合场景的共同地基，先把地基打扎实，后面几项才不返工。
⭐ 这是当前建议的起步项：它是关键字驱动、数据驱动、接口模块二期与 CI/CD 的共同前提。

阶段三 · 执行健壮性增强 📋 目标 1 个版本周期

  • 步骤级失败重试（次数 / 间隔 / 触发条件可配，默认关）
  • 显式等待（元素出现 / 消失 / 可点击）
  • 步骤间隔（全局 + 步骤级可配，替代散落的固定 sleep）
💡 打个比方：「网不好就重发」+「等人都到齐再开饭」——对车机这类慢响应场景尤其关键。

阶段四 · 测试套件增强 + 日志检索 📋 可穿插，见效快

  • 套件：级报告与通过率、套件内拖拽排序、链式执行（A→B）
  • 日志：按类型筛选 + 关键字搜索
💡 打个比方：「歌单出成绩单」+「微信搜聊天记录」——开发量小、见效快，随时可以插队做。

阶段五 · 关键字驱动 / 步骤模板 📋 中期

  • 关键字：把「登录」「搜索」等组合封装为可传参关键字
  • 步骤模板：保存成熟流程，任意用例插入复用
💡 打个比方：「快捷指令」+「Word 模板」——都是「变量 / 参数化」之上的复用层，必须等地基先稳。

阶段六 · 图像识别定位 + CI/CD 📋 进阶

  • 图像识别定位（模板匹配 + 相似度阈值，覆盖游戏 / 视频 / 自绘控件）
  • 命令行模式（headless + JUnit XML，接入 Jenkins / GitHub Actions）
  • 多设备并行（先解决底层设备对象线程安全）
💡 打个比方：「找不同」+「自动浇花」+「同时炒几锅菜」——进阶能力，工作量大，逐步推进。
