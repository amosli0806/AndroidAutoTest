1待办与扩展方向（按改动量排序）

从「改动小、见效快」到「改动大、影响面广」依次排列 —— 越靠前越建议先动。档位只反映改动量与风险，不代表价值：D 档（如关键字驱动）一旦做出来收益最大，只是要先有变量地基。

◆ A · 改动小、见效快（半天 ~ 1 天，可随时插进版本）

1. 测试套件增强 📋 规划中

  • 套件级执行报告与通过率　套件链式执行（A→B）
💡 打个比方：像「歌单」——用例按「冒烟测试」「回归测试」分组，跑完自动出这份歌单的「成绩单」（通过率），A 歌单放完自动放 B。（歌单内的顺序已经能拖拽调整了，还差「成绩单」和「连着放」。）

2. 步骤模板 📋 规划中

保存常用步骤组合为模板（如「启动应用 → 等待 → 点击首页」），任意用例里插入复用。

💡 打个比方：像 Word / PPT 模板——「启动 → 等待 → 点首页」这套成熟流程存成模板，新用例直接套用，不用每次从零搭。

3. 知识库增强（检索与关联）📋 规划中

现状：views/knowledge_view.py（1329 行）+ models/knowledge_model.py（747 行） 已具备「项目 → 分类 → 笔记」树、富文本编辑器（落库转 Markdown）、标签、全文搜索、图片资源、Markdown 导出。 基础功能够用，但提效交互几乎没有。

💡 打个比方：现在的知识库像一本装订整齐的笔记本 —— 纸和目录都不缺， 缺的是书签、索引卡和「上次看到哪儿」。

三个短板：① 无大纲、无快速跳转，搜索必须切到搜索页；② 只有行内代码（toggle_code）， 没有代码块，而内容里全是 adb 命令；③ 笔记之间完全孤立，没有关联与反向链接， 「踩坑」和「环境信息」互相指不到。

六个改造点（按投入产出排序）：

  • 代码块 + 高亮 + 复制 + 一键发到 ADB 工具箱执行（约 0.5 天）：贴合度最高 —— 复制完直接跑， 省掉切页面粘贴
  • 速查字段卡（约 0.5 天）：包名 / 启动 Activity / 账号做成键值行 + 一键复制， 把「每次翻笔记复制」变成「点一下」
  • 命令面板 Ctrl+P（约 1 天）：跨项目搜标题 / 正文 / 标签，还能直接执行 「新建笔记」「切换项目」。注意 Ctrl+K 已被「插入链接」占用，别撞键
  • 右侧「大纲 + 被引用」面板（约 1 天）：长笔记的结构感
  • 双链 [[笔记名]] + 反向链接（约 1.5 天）：在「踩坑」里写 [[环境信息]]， 右侧自动列出反向引用
  • 标签聚合视图（约 0.5 天）：模型里 all_tags() 已有，只差 UI，用来跨项目看「同一类坑」

差异化：一键记坑（别的工具没有）—— 在「自动化执行」的失败结果或「性能检测」的劣化告警上右键 「记为踩坑」，自动建笔记并填入设备型号、包名、失败步骤、日志尾部 50 行、当前截图， 自动挂到对应项目的「踩过的坑」下。测试真正浪费时间的是「事后回忆现场」，这条直接把现场钉住， 且完全复用已有的截图 / 日志 / 报告能力。

不改数据结构：以上全部落在视图层 + KbNote 现有字段上，Markdown 落库流程、 既有导入导出都不动。

开源参考（抄交互，不嵌代码）：VNote（Qt/C++，三栏 + 大纲 + 标签 + 多标签页， 技术栈同源，交互可直接平移）、QOwnNotes（Qt/C++，极简笔记列表的手感）、 思源笔记 SiYuan（块级引用 / 双链 / 反链面板，双链交互最好的范本）、 Trilium（层级 + 属性视图）、Logseq（命令面板与大纲的联动）。

🚫 不建议整包集成：AppFlowy / AFFiNE / Joplin / Outline 都要 Electron 或服务器， 与「绿色免安装桌面工具」的定位冲突，且安装包已经 440MB。
✅ 可嵌的组件：markdown-it-py + QWebEngineView（项目已用 QWebEngine）、 highlight.js / mermaid / KaTeX（离线打包即可）、 SQLite FTS5（Python 标准库自带，笔记量大时再上）。

建议起步：代码块 + 一键发 ADB（0.5 天）→ 速查字段卡（0.5 天）→ Ctrl+P 命令面板（1 天）。 三个做完「好用感」有明显质变，且都不动数据模型。

◆ 已知缺口与桩实现

当前尚未补齐、或做了半截的能力 —— 与上面的规划项互相呼应，是判断优先级时的依据。

📋
无分支与步骤级循环 — 没有 if/else，也没有「这段步骤重复 N 次」（执行页的「循环次数」只是整轮重复）。失败重试与显式等待已落地。
📋
无关键字复用 — 「登录」「搜索」等常用组合无法封装复用。
📋
套件能力不完整 — 无套件级报告、无链式执行（A→B）。
📋
GPU 采集缺失 — 渲染类指标（帧耗时分布 / GPU 占用）还没有采集手段；原方案的 GPU 仅支持高通 Adreno 且未接编排，属半成品。
📋
语音播报待增强 — 唤醒词不能按用例切换；「回执验证」只能确认车机听懂了，还验不了界面真的变了（如地图是否全屏）。
📋
无工程化配套 — 无 Git 集成（用例数据没有版本管理与回滚）。
📋
数据与参考图按绝对路径绑定 — 数据驱动绑定的 CSV / Excel、图像定位的参考图存的都是绝对路径，换机器或挪动工程目录后要重新绑定。

2macOS 移植注意事项 📐 2026-10-10 初评 · 2026-10-17 复核 · 未开始

目标：把虫师跑在 Mac 上，连车机做同样的测试。下面按「不改就跑不起来 / 能跑但行为不对 / 已经写好不用动」三类梳理，每条都标了确切文件；第五节为 2026-10-14 二次核查的新增发现。

一、不改就跑不起来

  • 依赖装不上：requirements.txt 里的 pywin32 / pywin32-ctypes 是 Windows 专有，macOS 上 pip install -r 会直接失败。要按平台拆（requirements-win.txt / requirements-mac.txt），或加环境标记 pywin32; sys_platform == "win32"。
  • 离线语音是 Windows 专有：services/voice_service.py 的 WindowsSapiEngine 走 win32com + SAPI。macOS 要么接系统 say / NSSpeechSynthesizer，要么只用跨平台的 Edge 在线语音（EdgeTtsEngine 已实现）。main.spec 里登记的 win32com.client / pythoncom 也要按平台去掉。
  • 数据会写进 .app 里：utils/app_paths.py::get_app_dir() 返回「exe 同级目录」。macOS 打包后 sys.executable 在 虫师.app/Contents/MacOS/ 内，往那儿写 data/ 会破坏 bundle（/Applications 下还可能只读，代码签名校验也会判为被篡改）。应改为 ~/Library/Application Support/虫师/。
  • 日志同样会写进 .app 里：utils/logger.py 的 LOG_DIR = "logs" 是相对路径（相对当前工作目录），main.py:55 的 app_debug.log 也是裸文件名 —— 打包后随启动方式不同会散落在 bundle 内或任意 cwd。要一并归到 ~/Library/Logs/虫师/（或与 data 同级的 ~/Library/Application Support/虫师/logs/）。
  • 打包脚本是 Windows 形态：main.spec 用的是 EXE(manifest=…)（Windows DPI 清单）、icon=.ico、COLLECT onedir。macOS 要改成 BUNDLE(...) + .icns，产物是 .app 目录。三个 spec（main / weditor / updater）各自都要处理。好消息：resources/icons/app_icon.icns 已经在了，图标素材不用另做；main.spec 里那段 _MANIFEST（DPI 清单）只在 Windows 有意义，macOS 分支要整个去掉，否则 PyInstaller 会报错。

二、能跑，但行为不对

  • 自动更新整体不可移植：updater.py 靠「等主程序退出 → 改名替换 exe 与 _internal」做热更新，全程 Windows API（kernel32 等进程、EnumProcesses 找占用者）。macOS 的 .app 是目录，且有 Gatekeeper / 公证与签名校验，替换内部文件会让应用起不来。macOS 上应改用 Sparkle 之类，或「下载 dmg → 引导用户替换」。
    补充：updater.py 顶层只 import ctypes（安全），ctypes.windll 都在函数内 —— 所以它不会 import 期崩，但一跑到 wait_for_exit() / 找占用进程就必然 AttributeError；且文件里没有任何非 win32 早退。macOS 上要么整条链路按平台禁用（主程序侧不提示「下载并更新」），要么重写。
  • 菜单栏托盘的平台差异不止提示语：macOS 托盘在菜单栏，setToolTip 无效、activated 的 Context 语义与 Windows 不同（左键单击即弹菜单是常态）、没有「双击」；自绘快捷面板（views/tray_controller.py）需按平台调整，或干脆改用原生 QMenu。注意：托盘面板里的「打开输出目录」还踩了上面那条 os.startfile 的坑。
  • 系统级通知：controllers/notification_controller.py 走 QSystemTrayIcon.showMessage（跨平台可用），但 macOS 的横幅通知需要用户授权、且「关闭最小化到托盘」的交互习惯不同（Mac 习惯关窗不退、由 Dock 收回），文案与默认行为都要重新考虑。
  • 单实例保护：现在用 Windows 命名互斥体（main.py::_acquire_single_instance，非 win32 已直接放行）。macOS 上要换成 QLocalServer 或文件锁。
  • 子进程「父死子亡」（weditor ＋ ADB 命令池）：这条目前靠 Windows Job Object 兜底 —— 实现已抽到公共模块 utils/win_job.py::bind_kill_on_close()，由 services/weditor_service.py（应用可视化）与 services/adb_command_pool.py（ADB 指令）共用（v1.4.8 修「残留一堆 adb 孤儿进程」时并入）。它在非 win32 直接返回 True（等于不绑），所以 macOS 上这层保护是空的：正常退出还能靠主动清理（_kill_process_tree / stop_all / atexit）收掉，但被强杀或崩溃时收不住（Windows 恰恰靠 Job Object 兜这两条路径）。macOS 没有等价的内核机制，只能把「进程组 + 退出时 kill」这条正常路径做扎实，或另找 launchd 之类的方案。
  • 字体：utils/theme.py 写的是 'Segoe UI', 'Microsoft YaHei'，日志区与报告的等宽字体是 Consolas —— 这些在 macOS 上都不存在。中文会由系统挑 CJK 回退、不至于乱码，但等宽字体要补 Menlo / SF Mono。views/splash_window.py 的 QFont('Microsoft YaHei')、utils/perf_report.py 与 views/help_view.py 的 HTML 字体同理（utils/api_report.py 已经带了 PingFang SC，可照抄）。
  • 内置工具是 Windows 二进制：tools/ 下的 scrcpy.exe 与一堆 dll（SDL2.dll／avcodec-61.dll／libusb-1.0.dll 等）只能在 Windows 用，macOS 要换 mac 版 scrcpy（建议改走 brew install scrcpy，同时把 tools/ 的 Windows 文件从 mac 包里排除）。（tools/take_help_screenshots.py、import_*.py 是开发脚本，不随包发布，可不管。）utils/adb_path.py 已按平台返回 adb / adb.exe，但 macOS 上得让用户 brew install android-platform-tools，帮助中心的安装指引（views/help_view.py「环境准备 → 安装 adb」）整段是 Windows 截图 + D:\platform-tools + 环境变量操作，需要一套 mac 版文案与截图。
  • 「打开所在文件夹」有四处是坏的：controllers/notification_controller.py、controllers/execution_controller.py、controllers/api_controller.py 用的是 os.name == 'nt' → os.startfile，否则 xdg-open，而 macOS 上没有 xdg-open，点了会静默失败；views/tray_controller.py::_open_output_dir（托盘面板「打开输出目录」）更彻底 —— 直接 os.startfile(p)，连平台判断都没有，macOS 上会抛 AttributeError。四处都应统一成 win32 / darwin / else 三分支 —— controllers/perf_controller.py 里已经是正确写法（os.startfile / open / xdg-open），照抄即可。
  • 字体还有漏网的（不止 theme.py）：除 utils/theme.py 的 'Segoe UI','Microsoft YaHei' 与 Consolas 外，还有 utils/dialogs.py:512 的 QFont("Segoe UI")、main.py:750 与 views/logs_view.py:165 的 QFont("Consolas", 10)、views/adb_dialogs/search_results_dialog.py 的 f.setFamily("Consolas")，以及一批 QSS 里的 font-family: Consolas, monospace（main_window / notification_center_view / perf_dialogs 等）。统一补 mac 回退：正文 PingFang SC、等宽 Menlo／SF Mono。
  • web 报告字体也不只是 perf_report：utils/report_generator.py:42（测试报告）用 'Segoe UI', Tahoma…、utils/perf_report.py:427 用 'Segoe UI','Microsoft YaHei'、views/help_view.py:918 同理 —— 都要照 utils/api_report.py 的做法带上 PingFang SC。

三、已经写好，不用动

  • subprocess.CREATE_NO_WINDOW：全项目都写成 if sys.platform == 'win32' else 0，非 Windows 传 0。
  • utils/adb_path.py：adb / adb.exe、scrcpy / scrcpy.exe 已按平台取名。
  • utils/wireless_manager.py：ping 次数参数 -n（Windows）/ -c（其他）。
  • services/adb_command_pool.py 的 _kill_process_tree()：Windows 走 taskkill /PID /T /F；POSIX 走 os.killpg(os.getpgid(pid), SIGTERM→SIGKILL)（配 preexec_fn=os.setsid 让子进程自成一个进程组），两处都套了 try/except —— macOS 可用。
  • utils/win_dark_title.py、utils/win_job.py::bind_kill_on_close（weditor_service._bind_kill_on_close 只是它的薄包装）、main._acquire_single_instance：都有非 win32 早退。
  • main.py 的 _PopenNoConsole（给子进程补 CREATE_NO_WINDOW 防黑窗）整段包在 if sys.platform == 'win32' 里，非 Windows 直接跳过 —— 正确（macOS 没有黑窗问题）。updater.py 是例外，见上面「能跑但行为不对」。
  • services/voice_service.py 的 EdgeTtsEngine（edge-tts 在线语音）本身跨平台，miniaudio 也支持 macOS —— 只要绕开 WindowsSapiEngine，语音播报主线可用。
  • 2026-10-17 新增的模块同样跨平台：utils/vars.py（变量替换）、utils/test_data.py（CSV / XLSX 数据驱动）、models/var_model.py、utils/no_context_menu.py（纯 Qt 事件过滤）、utils/image_match.py（OpenCV 模板匹配，opencv-python-headless 三平台通用）—— 都是纯 Python / 跨平台库，没有 Windows 专属调用；只需在 mac 上照常 pip install opencv-python-headless。

五、本次复核补充（2026-10-14 二次核查）

又按代码逐处扫了一遍，以下是前四节没提到的新发现。

  • QtWebEngine 是 macOS 上最大的一个坑：「应用可视化」内嵌的 weditor 用 QWebEngineView（services/weditor_service.py、views/main_window.py）。macOS 上它要求 ① 必须是真正的 .app（裸可执行文件起不来）；② PyInstaller 要带上 QtWebEngineProcess helper 并传 --osx-bundle-identifier；③ 一旦启用强化运行时／公证，必须加 com.apple.security.cs.allow-jit 与 com.apple.security.cs.allow-unsigned-executable-memory（Chromium 要 JIT），加载 http://localhost 页面还要 com.apple.security.network.client；④ 体积会明显变大（约 +200MB）。好消息：main.py 已在建 QApplication 之前设好 AA_ShareOpenGLContexts，macOS 同样必须有，这点不用改。
  • 图标还有一处是 .ico：main.py 的 app.setWindowIcon() 与 views/tray_controller.py 都读 resources/icons/app_icon.ico。Dock 图标由 .app 里的 .icns 决定（打包时设好即可），但菜单栏托盘图标需要「模板图」（单色 + setIsMask(True)）才能在浅色 / 深色菜单栏下都清晰；直接用彩色 .ico 会发糊，深色菜单栏下甚至看不清。
  • 离线语音还有一层注册表依赖：除 WindowsSapiEngine 走 win32com 外，services/voice_service.py 还用 HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Speech\AudioOutput 枚举音频输出设备；data/voice_data.json 里也存着 HKEY_LOCAL_MACHINE\...\TTS_MS_ZH-CN_HUIHUI 这类 Windows voice_id。macOS 上这块要整段换掉（走系统默认输出，或改接 say / NSSpeechSynthesizer）。
  • 字体又漏了两处新页面：views/easter_egg.py（彩蛋，3 处 Microsoft YaHei）与 views/knowledge_view.py（个人知识库代码块，Consolas, "Microsoft YaHei"）—— 都是 10-11 之后新增的，前文的字体清单没覆盖到。
  • 发版链路同样是 Windows 形态：release.py 写死 ROOT = r"D:\AndroidAutoTest"；.github/workflows/release.yml 用 runs-on: windows-latest、只产 虫师-{ver}-win64.zip；make_update_patch.py 也绑死在 updater 那套上。mac 版要单起 macOS runner，产物改 .dmg／.zip，并接签名 + 公证（codesign --options runtime → notarytool → stapler）；打包机需 macOS + Xcode 命令行工具。
  • 签名 / 公证后的首次打开：未签名或未公证的 .app 从网上下载会被 Gatekeeper 打上隔离属性，用户首次需右键「打开」或执行 xattr -dr com.apple.quarantine；随包分发的第三方可执行文件（adb、scrcpy）也要一并签名，否则会被拦。
  • 澄清一条容易误判的：tools/tcpdump 不需要 mac 版 —— 它是被 adb push 到设备 /data/local/tmp 再 chmod +x 执行的 Android 二进制（services/packet_capture.py），宿主是 Windows 还是 macOS 都一样。要换的只有本机跑的 scrcpy。
  • 需在真机（Mac）上实测的窗口行为：一批小窗口用了无边框 + 置顶 —— utils/toast.py（注释里写明「Dialog 比 Tool 在 Windows 下更稳」，是 Windows 取舍）、views/splash_window.py（Tool + 置顶 + 无边框）、utils/dialogs.py／views/task_view.py／views/element_manager_view.py 的 Frameless + Dialog、views/tray_controller.py 的 Popup 快捷面板。macOS 的窗口层级、是否抢焦点、是否进 Mission Control 规则都不同，需逐个实测；主窗口本身用的是系统标题栏，不受影响（无边框只用在菜单 / 弹窗上）。
  • 迁移到 mac 后要顺手改的数据：data/config.json 里的绝对路径（如 output_dir 存着 C:\Users\...\Desktop）在 mac 上无效，首次启动要重设输出目录；data/voice_data.json 里的 Windows voice_id 也要清掉。
  • 又确认几处「不用动」：① 主题「跟随系统」走 QApplication.styleHints().colorScheme()（Qt 6.5+），macOS 可用 —— win_dark_title 只影响 Windows 标题栏，macOS 系统标题栏自动跟随；② _warn_already_running() 里的 MessageBoxW 只会在 Windows 分支被执行（_acquire_single_instance 非 win32 直接 return True），macOS 碰不到；③ utils/serial_helper.py 只是文件名净化函数 safe_serial()，不是串口枚举，无平台依赖；④ 快捷键里写的 Ctrl+X 由 Qt 在 macOS 上自动映射显示为 ⌘X，无需逐条改。
⚠ 工作量估计：只求跑通「连车机 + 自动化执行 + 性能检测」这条主线，主要是 ① 拆依赖 ② 数据目录改到 ~/Library（含日志） ③ 改 main.spec 出 .app ④ 修四处「打开文件夹」 ⑤ 补字体回退，属小到中等改动；若连「自动更新 + 系统托盘 + 离线语音」也一并搬，则要大改 —— 这三块本质上依赖 Windows。另外注意：只要还想要「应用可视化 / weditor」，QtWebEngine 的打包 + 签名这条链就绕不开（第五节第一条）。
