2已知缺口与桩实现

这些是当前尚未补齐、或做了半截的能力，是下一步要优先解决的问题。

⚙️
帮助中心与文档一致性 — 已大幅推进（各章节补齐、图片高清、文案精简），基本无残留空占位。
📋
无变量 / 参数化 — 步骤参数写死，同一用例无法跑多组数据。
📋
无流程控制 — 没有 if/else 分支、循环、失败重试。
📋
无关键字复用 — 「登录」「搜索」等常用组合无法封装复用。
📋
无图像识别定位 — 对游戏 / 视频 / 自绘控件无能为力。
📋
套件能力不完整 — 无套件级报告、排序、链式执行。
📋
执行能力受限 — 仅单设备串行，无命令行 / 无 CI/CD 接入。
⚙️
性能检测维度不全 — 流量曲线、基线回归、启动耗时趋势已上线；缺 GPU / 系统内存 / 整机 CPU 等采集维度。
📋
语音播报空白 — 唤醒词只有一条、无车型模板、无法验证「真执行了」。
📋
无工程化配套 — 无 Git 集成、插件机制。

3扩展方向（按优先级）

16 项规划按「高 / 中 / 常规 / 进阶」四档组织，每项都配了一个生活化类比帮助理解。

◆ 高优先级 · 显著提升用户体验

1. 变量 / 参数化 📋 规划中

定义全局变量（设备序列号、测试账号、环境地址），步骤参数里用 ${变量} 引用；同一用例可循环跑多组数据（数据驱动）。

  • 全局变量表，元素库与步骤参数统一走一层变量替换
  • 从 CSV / Excel 读测试数据，同一用例循环执行多组数据
💡 打个比方：就像「填表模板」——表格里姓名、电话留成空格，谁来用就填谁的信息，不用为每个人重做一张表。同理，用例里把账号、设备号留成 ${占位符}，换账号换设备只改变量值，不必复制整份用例。

2. 批量操作增强 ⚙️ 部分完成

  • 批量修改定位方式（如全部「资源ID」→「XPath」）
  • 批量修改步骤参数（超时时间、等待时长、步骤间隔）
💡 打个比方：像 Excel 的「查找替换」——100 个步骤里所有「等待 3 秒」一次全改成「等待 5 秒」，不用一条条手改。

3. 接口模块二期 📋 规划中

  • 前后置脚本（Python 钩子，处理签名 / 加解密 / 数据提取）
  • 链路场景编排（接口串联，上一步响应作为下一步入参）
  • 数据驱动（与「变量 / 参数化」合并实现更合理）
💡 打个比方：前后置脚本像「做饭前的备菜 + 上桌前的摆盘」——请求前先签名、加密，响应后把数据提炼出来；链路编排像「接力赛」——上一个接口的返回，直接变成下一个接口的入参。

4. 变量 / 参数化落地到语音播报 📋 规划中

  • 把唤醒词、语速等提升为可参数化变量，用例内可覆盖
💡 打个比方：现在只有一句「你好虫师」打天下；将来像「对不同的人用不同称呼」——测本田车就喊「你好本田」，测小鹏车就喊「你好小P」，在用例里各配各的。

◆ 中优先级 · 增强灵活性与可维护性

5. 关键字驱动 📋 规划中

把常用动作组合封装成「关键字」（如「登录」「搜索商品」），支持传参，用例里点一下就复用。

💡 打个比方：像手机「快捷指令 / 宏」——把「打开 App → 输账号 → 输密码 → 点登录」这 5 步打包成一个「登录」关键字，以后任何用例点一下就好，不用重复拖 5 个步骤。

6. 步骤模板 📋 规划中

保存常用步骤组合为模板（如「启动应用 → 等待 → 点击首页」），任意用例里插入复用。

💡 打个比方：像 Word / PPT 模板——「启动 → 等待 → 点首页」这套成熟流程存成模板，新用例直接套用，不用每次从零搭。

7. 测试套件增强 📋 规划中

  • 套件级执行报告与通过率　套件内用例拖拽排序　套件链式执行（A→B）
💡 打个比方：像「歌单」——用例按「冒烟测试」「回归测试」分组，跑完自动出这份歌单的「成绩单」（通过率），还能拖拽排序，A 歌单放完自动放 B。

8. 执行健壮性增强 📋 规划中

  • 步骤级失败重试（次数 + 间隔 + 触发条件可配）
  • 显式等待（等元素出现 / 消失 / 可点击，替代固定 sleep）
💡 打个比方：失败重试像「网不好就重发消息」——点一下没反应，自动再试两次；显式等待像「等人都到齐了再开饭」，而不是「干等 5 分钟」——页面一加载好就继续，又稳又省时间。

9. 图像识别定位 📋 规划中

新增「图像」定位方式（模板匹配 + 相似度阈值），元素库可上传参考图，执行时截图比对。

💡 打个比方：像「人脸识别解锁」或玩「找不同」——游戏里的按钮是「画」出来的（不是代码控件，看不到元素树），靠截图比对把它认出来，从而覆盖游戏、视频、自绘界面。

◆ 常规优先级 · 提升效率与易用性

10. 语音播报增强 📋 规划中

  • 唤醒词多套管理（按用例 / 车型切换、多条候选轮播）
  • 车型模板（日志标签 + 关键词存成预设，换车一键套用）
  • 执行结果校验（除「被识别」，再验「真执行了」，如地图是否全屏）
  • 语音用例 ↔ 自动化用例互转
💡 打个比方：像「给不同车准备不同的话术模板」——每辆车的唤醒词、日志关键词都不一样，做成模板后换车一键套用，不用每次重新摸索；再进一步，还能验证「地图真的切成全屏了没有」，而不只是「车机听懂了没有」。

11. 性能检测采集能力并入 📋 规划中

  • 并入 mapauto-perf-test 的采集能力（GPU / 系统内存 / 整机 CPU 等，范围待定）
💡 打个比方：像「体检报告」升级——基础项目（CPU / 内存 / FPS / 流量）已能采集并自动对比基线，下一步是把更多「体检项目」（GPU / 整机 CPU 等）并入进来，一次查得更全。

12. 版本控制集成（Git）📋 规划中

把项目数据、步骤、元素库等接入 Git，支持版本回滚、差异对比、分支管理。

💡 打个比方：像文档的「修订记录 / 历史版本」——用例改乱了，一键回到昨天的版本，还能看看到底改了哪几行。

13. 测试数据管理 📋 规划中

从 Excel / CSV 读取测试数据，参数化执行同一用例多组数据（与「变量 / 参数化」合并实现更合理）。

💡 打个比方：像「同一张答题卡批不同试卷」——用例就是那张答题卡，数据就是试卷，套上账号 A、账号 B、账号 C 各跑一遍，批量出结果。

◆ 进阶扩展 · 面向高级用户与团队协作

14. 插件机制 📋 规划中

允许编写自定义 Python 脚本作为新动作类型，支持热加载。

💡 打个比方：像浏览器插件、微信小程序——开发者自己写个小功能挂进去，不用等官方排期，个性化需求自己动手。

15. CI/CD 集成（命令行模式）📋 规划中

提供无界面运行模式，命令行执行用例 / 套件，生成 JUnit XML 报告，接入 Jenkins / GitHub Actions。

💡 打个比方：像「自动浇花装置」——代码一提交，后台自动把全部测试跑一遍并出结果，人不用盯着屏幕。

16. 多设备并行执行 📋 规划中

单机多设备同时执行不同用例（需先解决底层设备对象的线程安全问题）。

💡 打个比方：像「同时炒几锅菜」——多台车机 / 多块屏同时跑不同测试，回归时间从 1 小时缩到 10 分钟。

7性能检测页 · 堆转储与抓包整合设计 📐 2026-10-02 设计稿

现状与痛点

  • 堆转储 / 抓包入口已从 ADB 工具箱挪到性能页底部「性能工具」卡片，但与监控会话完全脱节：产物不知道属于哪次监控，堆转储还要手动选进程。
  • 抓包依赖 root + /data/local/tmp/tcpdump，无时长 / 大小上限，长抓有撑爆设备存储的风险；未 root 要点进对话框才发现做不了。

设计原则（四条）

  • 目标自动对齐：监控哪个应用就转储谁、抓谁，不再手动选。
  • 事件进会话：转储 / 抓包动作写入会话时间线，报告可回溯到曲线上的那一刻。
  • 产物统一归档：按会话分目录存放，报告挂清单。
  • 防呆与保护：进行中防重复触发、未 root 前置置灰、抓包限时长限大小。

分层方案

  • A 入口层（工具卡片改造）：监控中点「堆转储」一键对当前监控应用转储（免弹窗），未监控才走原进程选择框；转储中按钮置灰显示「转储中…」。抓包按钮弹出精简参数（端口过滤 / 时长上限），开始后变「停止抓包」+ 红点计时；未 root 直接置灰并说明。停止监控时若还在抓包，自动收尾拉取。
  • B 会话联动层：PerfSession 新增 events 字段 [(时间戳, 类型, 文件路径, 备注)]；报告新增「诊断产物」章节按时间列出产物与相对秒，实时曲线在对应时刻画事件竖线；导出附带 events 清单。
  • C 产物管理：输出目录/perf/<会话名>/heap/*.hprof、capture/*.pcap；转储完立即删设备侧临时文件；抓包停止后立即 pull + rm。
  • D 场景化联动（二期）：场景化设置新增「用例前自动堆转储 / 用例期间自动抓包」，每用例一份产物，报告按用例分组。
  • E 阈值联动（三期）：内存超过阈值自动触发一次堆转储，抓住「涨上去那一刻」的堆，比事后手动转储更有诊断价值。

抓包保护（随 P0 一并做）

  • 时长上限默认 10 分钟、文件大小上限默认 100MB，到限自动分段存盘；设备剩余空间不足时提前告警收尾。

实施拆期

  • P0：A + B + C + 抓包保护 —— 入口联动、事件记录、报告段落（perf_view / perf_controller / perf_model / perf_report + 工具箱能力下沉为公共 service）。
  • P1：D 场景化按用例自动触发。
  • P2：E 阈值自动转储、抓包分段与空间告警增强。
💡 关键收益：堆转储 / 抓包从「孤立的手动工具」变成「监控会话的诊断动作」——报告里既有曲线，又有曲线关键时刻的堆和包，内存问题才查得下去。
