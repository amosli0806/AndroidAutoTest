===== 发版（2026-09-24 起用脚本，一条命令搞定）=====

推荐方式（自动）：在项目目录 D:\AndroidAutoTest 打开命令行，执行
    python release.py 1.1.5              # 发 1.1.5：自动改版本号→写 CHANGELOG 占位→commit→push main→打 tag 推送（触发 CI）
    python release.py 1.1.5 --dry-run    # 只演练，不改文件、不提交
脚本自动做 5 件事：改 utils/version.py 的版本号与构建时间 → 在 CHANGELOG.md 顶部插入 "## v1.1.5" 占位段 → git add+commit+push main → git tag+push tag（触发 CI 自动打包发版）。
要点：
  - 幂等：重复执行安全（同名 tag 会先删本地再重打）。
  - CHANGELOG 插入的是占位文字：可发版前先手动改好 CHANGELOG.md（脚本检测到该版本段已存在则不覆盖），或发完到 GitHub 网页编辑 Release 正文。
  - 发版前先 git pull 拉最新，避免覆盖别人改动。
  - 成功标准：push tag 后看到 "* [new tag] v1.1.5"；结果看 https://github.com/amosli0806/AndroidAutoTest/releases

手动方式（脚本出问题时兜底，四步）：
  1. 改 utils/version.py 的 APP_VERSION 为 1.1.5
  2. 在 CHANGELOG.md 顶部加 "## v1.1.5" 段写说明
  3. git add -A && git commit -m "发布 v1.1.5" && git push origin main   ← 先传代码（不触发发版）
  4. git tag v1.1.5 && git push origin v1.1.5   ← 打 tag 触发 CI：校验版本→打包主程序+更新器→自测→压 zip→建 Release

【性能检测】✅

【语音播报】✅ 新增能力（原文档未记录）
- 定位：声学耦合 —— 电脑扬声器放音，车机麦克风拾音后交给车机自己的语音助手，
  不与车机做任何协议对接；解决"声音从哪个扬声器出去"和"每句之间等多久"
- 三栏结构：语音管理（独立语音用例库：分组 → 用例 → 文案）/ 用例步骤（文案增删改 + 单条播报）/
  执行（勾选要播的用例、语速、循环、执行选中、停止）
- 语音用例管理：分组与用例的新建、复制（分组递归复制组内用例）、重命名、删除，
  右键菜单带图标并适配日夜模式；文案级导入/导出 JSON
- 唤醒词：中栏「唤醒词」按钮一键把配置好的唤醒词追加成一条文案（未选用例时置灰），
  文案在「设置 → 语音播报」配置，留空回落到默认值，改完立即生效
- 执行：整行点击即可勾选；分组勾选级联；语速（SAPI -10~10）与循环次数；
  「停止」会立刻打断当前这句（后台线程持有 SAPI 对象，主线程调 stop() 打不断）
- 设置页「语音播报」：引擎 / 音色 / 输出设备 / 唤醒词，支持试听；响度走系统音量，程序内不调音量
- 与「自动化编辑」里的语音播报步骤共用同一套音色、语速与输出设备配置

【系统与体验】✅

- 设置中心：主题、壁纸、输出目录、快捷键、AI 配置、语音播报、设备维护（恢复输入法）

   - 语音用例与「自动化编辑」用例是两套独立数据，无法互相引用或一键转换

📋 13. 无工程化配套
   - 无 Git 集成（版本回滚/差异对比/分支）
   - 无插件机制、无多语言（i18n）、无云端同步

四、优先级与实施建议
============================================================

优先级	功能模块	理由
⭐⭐⭐	变量 / 参数化	数据驱动是自动化测试的核心能力，是关键字驱动与数据驱动共同的地基
⭐⭐⭐	日志过滤与搜索	改动集中在 LogsView，开发成本低、调试收益立竿见影
⭐⭐⭐	批量操作增强	批量改定位方式/步骤参数是高频诉求，效率提升显著
⭐⭐⭐	补齐桩实现与文档	复杂手势序列为桩，直接影响用户信任（文档侧已基本补齐）
⭐⭐	执行健壮性（重试 + 显式等待）	直接影响用例稳定性与回归可信度
⭐⭐	测试套件增强	套件级报告与排序，提升组织与执行效率
⭐⭐	接口自动化最小闭环	入口已存在但完全为空，先做 HTTP + 断言 + 报告即可用
⭐⭐	关键字驱动	封装复用，降低用例编写成本
⭐	语音播报增强	播报-识别闭环对声学耦合场景价值突出，但依赖 ASR 能力
⭐	性能检测增强	温度/电量、流量曲线、自动基线回归，对车载场景价值突出
⭐	命令行模式	价值高但开发量适中，是打开 CI/CD 的钥匙
⭐	图像识别定位	覆盖面广，但引入 OpenCV 依赖，工作量较大

五、立即推荐的下一步开发
============================================================

基于当前项目定位（为测试初学者提供便捷的自动化能力），建议优先实现：

1. 变量 / 参数化
   引入全局变量表与 ${var} 渲染层（在 DeviceService.perform 之前统一替换），
   打通元素库与步骤参数，后续可平滑扩展 CSV 数据驱动。

2. 日志过滤与搜索
   在 LogsView 增加类型筛选下拉与关键字搜索框，复用已有四色日志与统计圆盘。

3. 批量操作增强
   步骤列表批量修改定位方式、批量更新步骤参数（超时/等待/间隔）。

4. 接口自动化最小闭环
   把已有的占位入口做成可用：接口管理（路径/方法/头/体）+ 环境变量 + 状态码与响应体断言
   + 复用现有 HTML 报告风格。这是唯一"入口已在、内容全空"的模块，补齐后功能全景才完整。

另外两项工作量小、见效快，可作为穿插任务：
   - 复杂手势序列：实现或下架（当前点卡片只打印一行日志，属误导）
   - 语音播报增强：唤醒词多套管理 + 播后等待批量调整（都在现有页面上小改即可）

这四项对现有架构改动较小，且能显著提升用户体验与产品可信度。
